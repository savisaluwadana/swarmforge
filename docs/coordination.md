# Coordination protocol: scoped authority, not a consensus invention

## Research hypothesis
A hybrid scheduler with pre-delegated task authority may maintain higher throughput than a centralized dispatcher during controller outages and network partitions, without increasing conflicting assignments under the stated crash-stop and simplified physical model. Compare with a local auction baseline; this is not a claim of novelty, general consensus or exactly-once physical action.

## Model
Rectangular integer grid, static obstacles, pickup/dropoff points, unique starts, unit speed (one orthogonal step or wait each tick), no battery in P0. Tasks released at explicit tick, priority 0–9, optional due tick, unique package ID. Each robot has capability tags, local inbox, position, task, mode (idle, assigned, moving_to_pickup, carrying, moving_to_dropoff, waiting, failed), local authority cache. Controller node C and robot nodes r1..rN. Directed links with delay >=1 tick and drop rate 0..1. Network send schedules envelope {message_id, sender, receiver, sent_tick, deliver_tick, kind, body}; links checked at send and delivery; partition blocks selected links, heal does not resurrect dropped envelopes. Crash-stop halts robot; optional recovery requires explicit fault; failed robot occupies its cell and blocks motion until removed by explicit scenario assumption (not modeled in P0). No Byzantine nodes, malicious messages, real clock skew, physical dynamics or safety certification.

## State and invariants
Task state: pending -> assigned -> picked -> completed; assigned -> pending after safe release; picked -> stranded on crash, no automatic reassignment. Unpicked assigned task can be cancelled only in demo via run cancellation; no task editing mid-run. Pending tasks may be deferred; overdue is a derived flag, not state. Invariants:
I1 unique task ID/package ID within run, one authoritative active assignment per task.
I2 every pickup/dropoff validated against holder+epoch+lease and correct location; completed task cannot transition again. Log rejected stale commands. 
I3 never auto-reassign picked/uncertain tasks, fence expired authority before granting new authority. If remote holder cannot be proven stopped or state cannot be reconciled, defer task.
I4 no simultaneous vertex occupancy or opposite-edge swaps; all moves validated by common physical arbiter, including blocked/failed cells. Count attempted conflicts separately from actual collisions; if arbiter invariant fails terminate run and preserve evidence.
I5 no robot observes global oracle except physical safety results; policy views sourced only from modeled messages and local sensors. 
I6 task completion count <= released; no fabricated completions. 
I7 same manifest and engine version -> same normalized trace digest for scripted run. 
I8 no execution without authority at action tick. Safety and throughput trade off; no universal availability in a partition.

## Three policies
B1 centralized_greedy: controller receives heartbeats/status, assigns pending tasks to reachable idle robots using integer score = travel estimate + deadline penalty - priority weight, ties task ID then robot ID; uses acknowledged grant and completion notices; no new work granted during outage; active authorized work can continue within grant. Controller never uses simulator truth to decide. B2 local_auction: robots receive task announcements and broadcast bids using same score; bounded 3 tick bid round, winner locally chosen by (score, robot_id), stale bids rejected; use common authority validator, count rejected duplicate proposals. During partition distinct components may propose same work; authority prevents conflicting accepted actions in model, so show conflicts and lost availability honestly. Label simplified auction, not full CBBA. B3 scoped_lease (experimental): controller delegates non-overlapping task scopes to preconfigured zones before fault. Scope owner is deterministic local leader for healthy connected zone; no automatic leader election in P0. Task scope = pickup zone; local tasks only if pickup/dropoff and planned route inside that zone. Globally shared/cross-zone tasks require controller. Each scope has an epoch, lease_until_tick, authorized leader ID and allowed task IDs or deterministic task namespace. Controller relinquishes concurrent authority for that scope; local leader grants subtasks to zone members using local auction. No overlapping grants; no scope renewal without controller connectivity. All task grants expire no later than parent scope grant. Zone leader crash or scope expiry => stop new assignments, defer unresolved tasks; preauthorized nonconflicting tasks can continue only before expiry. 
For comparable workloads, all policies share movement, grant validator and same task release/network conditions; report warmup authority allocation overhead. Scoped lease may be slower in normal operation, under long outages, or with skewed workloads.

## Authority implementation
Explicit modeled authority ledger contains scope+epoch+holder+start+expiry, task grants {task_id,epoch,holder,expires_tick,scope_epoch}; simulator gate checks grants as a modeled execution-side fencing mechanism, not a cross-partition communication service. Issuance can only occur through policy agent holding valid authority via modeled messages; never let ledger choose winner or expose global task state to scheduler. Grants/revocation acknowledgements travel over emulator. Controller can grant higher epoch only after previous expires and prior execution state is known safe (acknowledged not picked, or proven crash before pickup by modeled evidence); otherwise defer until reconciliation. For P0 use shared virtual clock with zero skew; production requires durable distributed authority, fencing at actual actuator/work source, clock bounds, local safety and validation. A gate rejecting stale action is an assumption of simulated enforcement, not proof real robots honor fences.
When partition heals, agents exchange summaries {scope,epoch, task_id, phase, last_event}; dedup by message_id; higher epoch accepted only from authorized issuer. Conflicting/uncertain phase -> stranded/deferred for human reconciliation; completed remains terminal. Never resolve physical side effects by last-write-wins.

## Path planning and physical truth
Space-time A* with Manhattan heuristic, state (x,y,t), wait action, fixed 4-neighbor order, horizon 32 default, stable tie-break. Local planner may use received reservations only; common physical arbiter receives next-move proposals, rejects obstacles, occupied cells that won't vacate, duplicate target cells and edge swaps. Resolve by stable robot ID, iterate to fixed point so a rejected robot staying cannot be struck. Conservative P0: disallow entering any currently occupied cell even if vacating; prevents swaps and may reduce throughput. If no path, wait/replan; detect >=20 ticks without progress, emit deadlock_suspected (do not teleport). Failed robots are stationary obstacles. All policies use identical rules. This abstraction is deliberately more conservative than realistic multi-agent motion; document limitations.

## Fault types
controller_outage targets C; partition lists directed link pairs; robot_crash targets robot; latency adds integer ticks to specified links; packet_loss sets probability; heal is scheduled end_tick restoring prior baseline. Overlapping faults on same target/type are rejected in P0 or use explicit precedence (reject for now). Controller crash differs from link outage only if state loss explicitly modeled; P0 controller_outage is link isolation. Faults applied before message delivery. In-flight drops visible. Permanent fault end_tick null. Robot crashes are permanent in P0; no implicit recovery.
